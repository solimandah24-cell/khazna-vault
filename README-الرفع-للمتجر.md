# خزنة — دليل الرفع كـ PWA وتغليفها لمتجر Google Play

## 📁 هيكل الملفات (ارفع كل هذا لمستودع GitHub كما هو)

```
your-repo/
├── index.html                    ← التطبيق نفسه
├── manifest.json                 ← بيانات التطبيق (الاسم، الأيقونات، الألوان...)
├── sw.js                         ← Service Worker (يشغّل التطبيق بدون إنترنت)
├── icons/
│   ├── icon-192.png
│   ├── icon-512.png
│   ├── icon-maskable-512.png
│   ├── apple-touch-icon.png
│   └── favicon.png
└── .well-known/
    └── assetlinks.json           ← يُستخدم لاحقًا فقط عند تغليف تطبيق أندرويد (TWA)
```

⚠️ **مهم جدًا:** لا تغيّر أسماء الملفات أو أماكنها، لأن `index.html` و`manifest.json` و`sw.js` يشيرون لبعضهم بأسماء نسبية بالضبط كما هي.

---

## 1) الاستضافة عبر GitHub Pages (الخطوة الأولى الإلزامية)

التشفير المحلي (Web Crypto) و Service Worker **لا يعملان إلا عبر HTTPS** — فتح الملف مباشرة من جهازك (`file://`) لن يفعّل هذه الميزات.

**الخطوات:**
1. ارفع مجلد المشروع كما هو إلى مستودع GitHub.
2. من إعدادات المستودع: **Settings ← Pages ← Source: Deploy from a branch ← اختر الفرع (main) والمجلد (root)**.
3. بعد دقيقة أو اثنتين سيصبح تطبيقك متاحًا على رابط مثل:
   `https://username.github.io/repo-name/`
4. افتح الرابط من جوالك (كروم على أندرويد / سفاري على آيفون) وجرّب "إضافة إلى الشاشة الرئيسية".

---

## 2) التحقق من جاهزية PWA (قبل التغليف)

من متصفح Chrome على الكمبيوتر:
1. افتح رابط موقعك.
2. اضغط F12 (أدوات المطوّر) ← تبويب **Application** ← **Manifest**: تأكد أن كل الحقول تظهر بدون أخطاء، والأيقونات تظهر بشكل صحيح.
3. تبويب **Service Workers**: تأكد أنه مسجّل (Status: activated).
4. شغّل تدقيق **Lighthouse** (تبويب منفصل) واختر فحص "Progressive Web App" — يجب أن تظهر علامة ✅ خضراء لمعظم البنود.

إذا ظهرت أخطاء هنا، **أصلحها قبل الانتقال للتغليف** — نفس الأخطاء ستمنع قبول التطبيق لاحقًا في أدوات التغليف أو حتى في مراجعة المتجر.

---

## 3) تغليف التطبيق لمتجر Google Play (أندرويد)

الطريقة القياسية والمعتمدة من Google نفسها هي **TWA — Trusted Web Activity**: تطبيق أندرويد حقيقي (بصيغة `.aab`) يعرض موقعك PWA بدون أي شريط متصفح، ويبدو كتطبيق أصلي بالكامل. **هذا لا يحتاج كتابة كود Java/Kotlin.**

### الأداة الأسهل: PWABuilder (بدون تثبيت أي شيء)
1. اذهب إلى: **https://www.pwabuilder.com**
2. ألصق رابط موقعك (من GitHub Pages) واضغط تحليل (Start).
3. بعد التحليل، اختر **Android** ← حمّل الحزمة الجاهزة (Android package).
4. سيولّد لك PWABuilder:
   - ملف `.aab` (Android App Bundle) جاهز للرفع على Google Play مباشرة.
   - **مفتاح توقيع (signing key)** — **احتفظ به في مكان آمن جدًا**، لأنك ستحتاجه لكل تحديث مستقبلي للتطبيق، ولا يمكن لأحد (ولا حتى Google) استرجاعه إذا فقدته.
   - بصمة **SHA-256** الخاصة بمفتاح التوقيع، واسم الحزمة (package name).

### الأداة البديلة (للتحكم الأدق): Bubblewrap CLI
أداة رسمية من Google، تُستخدم عبر Terminal:
```bash
npm install -g @bubblewrap/cli
bubblewrap init --manifest=https://username.github.io/repo-name/manifest.json
bubblewrap build
```
ستُسأل عن اسم الحزمة (مثل `com.yourname.khazna`) وتفاصيل التوقيع، وتنتج نفس ملف `.aab`.

### ربط الموقع بالتطبيق (Digital Asset Links) — خطوة إلزامية
لكي يعرض التطبيق موقعك **بدون شريط عنوان المتصفح**، يجب أن يثق أندرويد أن التطبيق والموقع مملوكان لنفس الجهة. لهذا:
1. خذ **اسم الحزمة** و**بصمة SHA-256** التي حصلت عليها من PWABuilder أو Bubblewrap.
2. عدّل ملف `.well-known/assetlinks.json` المرفق في هذا المشروع وضع فيه القيمتين بدل النص الوهمي.
3. تأكد أن الملف يظهر على: `https://username.github.io/repo-name/.well-known/assetlinks.json`
   *(ملاحظة: إذا كان موقعك تحت مسار فرعي مثل GitHub Pages العادي، هذا الملف يجب أن يكون في جذر الدومين وليس تحت مسار المستودع — قد تحتاج دومينًا مخصصًا (Custom Domain) لهذه الخطوة تحديدًا، وهو أمر شائع وسهل الإعداد من إعدادات GitHub Pages).

### الرفع على Google Play Console
1. أنشئ حساب مطوّر على **https://play.google.com/console** (رسوم اشتراك لمرة واحدة 25 دولارًا).
2. أنشئ تطبيقًا جديدًا، واملأ بيانات المتجر (الاسم، الوصف، لقطات الشاشة، الأيقونة، سياسة الخصوصية).
3. ارفع ملف `.aab` تحت **Production ← Create new release**.
4. أرسل للمراجعة (عادة تأخذ من يوم إلى بضعة أيام).

⚠️ **متطلب إلزامي:** يجب أن يكون لديك **رابط سياسة خصوصية (Privacy Policy)** منشور وحقيقي، خصوصًا لأن تطبيقك يتعامل مع بيانات حسّاسة (كلمات مرور، بطاقات بنكية). اذكر فيها بوضوح أن البيانات تُخزَّن محليًا فقط ومشفّرة، ولا تُرسل لأي خادم — وهذا ميزة تسويقية قوية لك أيضًا.

## 4) بخصوص iOS / App Store — بصراحة تامة

هذه النقطة مهمة جدًا ولا أريد تضليلك فيها:

- **لا يوجد لأبل مكافئ لـ TWA.** أندرويد يسمح بتطبيق حقيقي "يعرض" موقعًا بثقة كاملة، أما أبل فلا تقدّم هذه الآلية.
- تطبيقات الويب المُغلَّفة في WebView بدون أي وظيفة أصلية إضافية غالبًا **تُرفض من مراجعة App Store** بموجب البند 4.2 (Minimum Functionality) — أبل تعتبرها "مجرد موقع في صندوق".
- الخيارات الواقعية:
  1. **الاعتماد على PWA فقط على آيفون**: يفتح سفاري ويضغط المستخدم "إضافة إلى الشاشة الرئيسية" — يعمل كتطبيق مستقل بأيقونته الخاصة، **لكن بدون وجود في App Store**. هذا يعمل بالفعل الآن مع ما جهّزناه.
  2. **استخدام Capacitor** (من نفس فريق Ionic) لتحويل التطبيق لتطبيق iOS حقيقي عبر Xcode، **مع إضافة قيمة أو وظائف أصلية حقيقية** (مثل ربط حقيقي بـ Face ID عبر Keychain، إشعارات، إلخ) لزيادة فرصة قبوله في المراجعة. هذا يحتاج جهاز Mac وحساب Apple Developer (99$/سنويًا) وجهدًا إضافيًا في التطوير، وليس ضمانًا للقبول.
- إذا كانت أولويتك الأولى إطلاق سريع، أنصح بالبدء بـ **أندرويد عبر TWA** (مضمون ومباشر أكثر بكثير)، ثم التعامل مع iOS كمرحلة لاحقة عبر Capacitor إذا قررت الاستثمار في تطبيق أصلي فعلي.

|---|---|---|
